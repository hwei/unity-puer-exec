## 2. Settled-import timestamp

Implementation complete in `UnityPuerExecImportChangeTracker.cs` (SessionState-persisted `UnityPuerExec.SettledImportUtcTicks`, advanced only from the completion hooks). The real-host test `test_code_change_refreshes_once_then_does_not_refresh_again` covers the loop-breaking property end to end, and `test_settled_timestamp_survives_domain_reload` / `test_exec_and_refresh_do_not_advance_settled_timestamp` cover the persistence and single-writer properties. A real-host run has confirmed them (see `results/real-host-evidence-20260920-signal-tasks.md`).

- [x] 2.1 Add a persisted project-wide settled-import timestamp to the Editor package and confirm by test that it survives a domain reload. Verify: a test triggers a reload and asserts the timestamp value is unchanged across it. Covered by real-host `test_settled_timestamp_survives_domain_reload`: it asserts the live field and the persisted `SessionState` value agree, forces a domain reload, and asserts the reload is not treated as a pending change (health `not_pending`, next exec `triggered:false`). The reload's own completion signal legitimately advances the timestamp (spec: an assembly reload advances it), so the test asserts the baseline is never lost and is still persisted rather than literal tick equality. The persistence load path is exercised directly: `Shutdown()`, zero the in-memory field, plant a persisted baseline, and `Install()` restores exactly that value.
- [x] 2.2 Advance the timestamp from the confirmed Unity completion hooks only, and assert by test that a refresh or an exec never advances it. Verify: a test performs a refresh that triggers no compilation and asserts the timestamp did not move. Covered by real-host `test_exec_and_refresh_do_not_advance_settled_timestamp`: a plain exec leaves the ticks unchanged, and an explicit `AssetDatabase.Refresh()` with nothing to compile leaves them unchanged. The source invariant is pinned by `tests/test_refresh_change_signal.py::test_settled_timestamp_has_a_single_writer`.
- [x] 2.3 Add a test proving the no-repeat-refresh property: after one change is imported and settled, a second exec does not refresh again, while a genuinely new change does. Verify: both assertions pass; this is the loop-breaking test from the design's highest-severity risk.

## 3. Change signal

Implementation complete in `UnityPuerExecImportChangeTracker.cs` (per-root `FileSystemWatcher` over `Assets/` and `Packages/`, compile-triggering extension filter, thread-safe candidate set, error-event fallback, install-time baseline walk). Real-host test `test_non_code_asset_change_does_not_refresh` covers the boundary; `test_non_code_writes_do_not_mark_dirty`, `test_watcher_error_invalidates_signal_then_forces_one_refresh`, and `test_change_made_before_install_is_caught_by_baseline_walk` cover the remaining assertions, and `tests/test_refresh_change_signal.py` pins the callback-path source invariants. A real-host run has confirmed them (see `results/real-host-evidence-20260920-signal-tasks.md`).

- [x] 3.1 Add a filesystem watcher over `Assets/` and `Packages/` filtered to compile-triggering extensions (`.cs`, `.asmdef`, `.asmref`, `.rsp`), excluding `Library/`, `Temp/`, `Logs/`, and `.git`. Verify: a test writes a `.cs` file and observes a dirty signal.
- [x] 3.2 Assert by test that non-code writes do not mark dirty: `.unity`, `.prefab`, `.meta`, texture, and audio changes produce no signal. Verify: each extension has a negative test case. Covered by real-host `test_non_code_writes_do_not_mark_dirty`, which writes one file per excluded extension and asserts health stays `not_pending` and the next exec reports `triggered:false` (the existing `test_non_code_asset_change_does_not_refresh` keeps the real-import `.txt` case). The extension filter itself is pinned by `tests/test_refresh_change_signal.py::test_compile_triggering_extensions_are_code_only`.
- [x] 3.3 Debounce watcher events into a candidate path set on a thread-safe collection, with no Unity API touched from the callback thread. Verify: a test asserts callbacks only mutate the collection; review confirms no Unity API call in the callback path. Coalescing is the case-insensitive `HashSet` candidate set mutated only under `Gate`; every `[UPE-DIAG]` `Debug.Log` that previously sat in the callback path was removed so the handler now calls no Unity API (the error diagnostic is recorded as plain state and drained on the next request-thread access). Enforced by `tests/test_refresh_change_signal.py` (`test_watcher_callbacks_touch_no_unity_api`, `test_callbacks_coalesce_into_a_thread_safe_candidate_set`, `test_callbacks_are_wired_to_every_relevant_watcher_event`).
- [x] 3.4 Mark dirty on watcher error events including `InternalBufferOverflowException`. Verify: a test simulates the error event and asserts the dirty state. Covered by real-host `test_watcher_error_invalidates_signal_then_forces_one_refresh`: it applies the exact state an error event sets (`signalValid=false` plus the deferred detail), asserts health reports `unknown`, asserts the next exec treats the project as changed (`triggered:true`, `reason:watcher_signal_unavailable`) and still runs the script, and asserts trust is then re-established so the following exec is an ordinary no-change exec. `OnWatcherError` setting that state is pinned by `tests/test_refresh_change_signal.py::test_watcher_error_invalidates_the_signal`. A real error event cannot be raised from outside on Windows (the embedded-Mono watcher is silent), which is why the state is applied directly.
- [x] 3.5 Run a baseline walk at watcher-install time against the persisted timestamp so pre-attach changes and post-reload state are caught. Verify: a test changes a file before install and asserts the post-install state is dirty. Covered by real-host `test_change_made_before_install_is_caught_by_baseline_walk`: `Shutdown()`, then write a `.cs` with no watcher state present, then `Install()`, and assert the pending state is `Pending` both in-process and on `/health`.
- [x] 3.6 Bound the invalidated-signal fallback to a single refresh and re-establish trust from the decision's own scan, so an invalidation that missed nothing cannot become an unconditional per-exec refresh. Verify: a test asserts one forced refresh, `reason: watcher_signal_unavailable`, `unknown` health before the decision consumes it, and an ordinary no-change decision afterward. Covered by real-host `test_watcher_error_invalidates_signal_then_forces_one_refresh`; requirement `import-change-refresh / An invalidated signal forces one refresh, then re-establishes trust`.
